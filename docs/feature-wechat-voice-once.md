# 微信浏览器语音失败说明（2026-10-04）

微信 UA 只决定菜单说明，不能用来判断语音失败。只有实际缺少 Web Speech API、真实 utterance 报错或没有 start/end/error 而超时，才显示朗读失败。静音与关闭朗读不算故障；音效失败也不能改变朗读状态。检测不会自动发出有声探测。

在父层恢复 `voice=true` 后，明确缺失 API 的浏览器无需等首次手势即可显示说明。服务构造时不报告缺失，因为那时尚不知道玩家偏好。真实合成接口失败时，声音设置显示「暂不可用」且开关仍可操作。

主页第一次出现可关闭说明，提供微信右上角菜单、Chrome / Edge / Safari / 安卓版等实际选择，不提供网页强行跳出微信的假按钮，也不保证任何特定设备能听见。关闭后 `DB.audioNoticeSeen.speech` 或 `.sfx` 记为 `true`，沿用 `wy8a_rogue_v1` 与唯一存档提交点。既有及未知字段保留；不新开存储 key，不改 `voice`、`mute`、`vol`。没法保存时保留会话内关闭，玩法继续。

再次失败或刷新后，已关闭的主动说明不再显示，真实失败状态与折叠「声音使用帮助」仍可查看。微信里即使 API 报成功，也保留默认折叠的条件说明「如果没有听见读音」，供用户主动展开，不据此报故障或自动弹提示。音效和朗读的关闭事实独立；已看过的音效说明不能遮住尚未看过的朗读说明。两路状态分别参与去重发布，因此较严重的音效错误不会吞掉朗读的后续状态更新。重绘不会关闭用户展开的帮助，也不会替换内容未变的关闭按钮。

服务端口：`channelSnapshot(channel)`；`dismiss(channel)` / `isDismissed(channel)`，不传 channel 时仍兼容原调用。UI 可选端口：`getNoticeSeen(channel)` / `onNoticeSeen(channel)`。UI 只读显式端口，不读存档、不负责存储。

浏览器验证只替换平台 API，真实游戏负责按钮、输入、暂停、继续与存档。覆盖 API 缺失、语音拒绝、静默超时、微信 UA 但 API 成功、音效坏而语音正常、关闭后刷新和继续、未知字段及进行中远征保持。320px 截图确认说明与折叠帮助没有横向溢出。

Web Speech API 的事件及错误语义依据[规范](https://wicg.github.io/speech-api/#speechsynthesisutterance)；UA 不能证明系统合成服务实际可听。没有验证微信 iOS / Android 真机发声，也无法通过脚本识别设备物理静音或操作系统报告成功却实际静默的情况。
