# 暂停与进度保存

玩家在手机上游玩中途退出、切后台、或者干脆杀掉页面，都不该丢进度。本文档说明这套机制的实现契约、跨刷新的取舍，以及明确的已知边界。

## 一句话模型

把「当前这一局」写成一份**版本化快照**放进存档的 `activeRun` 字段；暂停时冻结所有会改状态的入口并把快照存盘；刷新后玩家在主页点「继续远征」主动恢复。

## 存档形状

存档 key 仍是 `wy8a_rogue_v1`，既有字段与未知字段原样保留，只**新增**一个键：

```jsonc
{
  "runs": 3, "wins": 1, "mastered": ["litre"], "best": 4,   // 既有字段不动
  "activeRun": {                                             // 新增
    "schemaVersion": 1,
    "savedAt": "2026-10-01T12:00:00.000Z",
    "phase": "battle",
    "run":    { /* 见下 */ },
    "battle": { /* 战斗事实，地图/事件相位为 null */ },
    "encounter": null                                        // 事件/商店/奖励的已展开描述
  }
}
```

### 三条硬约束

1. **学习 DB 与快照同一次 `storage.save(DB)` 提交。** 分两次写就会出现「金币已发、快照还停在上一帧」的窗口，刷新后用旧快照恢复就会二次发奖。`services/progress.js` 的 `commit()` 是唯一写入点。
2. **`G.done` 落盘成数组，回来时必须重新是 `Set`。** `drawWord` 用 `run.done.has()` 判退休；变成数组会让「本局已答对的词」重新出现。
3. **地图节点必须保身份。** 旧版 UI 的判定是 `G.avail.indexOf(n) >= 0`、`G.node === n` 这类**对象身份**比较。所以 `links` 落盘成 nodeID（`r<row>_x<量化后的x>`），解码时按 ID 重新指向 `rows` 里的同一批对象；`avail` / `cur` / `node` / `battle.node` 也必须是这些对象本身。只复制值会让恢复后的地图变成一层都点不动的死局。

### 不落盘的东西（有意为之）

计时器、闭包回调、DOM/`innerHTML`、`B.keyEls`、`availSig` 这类纯 UI 派生缓存。它们要么无法序列化，要么恢复时重算即可。

## 相位：跨刷新的待办怎么重建

`phase` 是**恢复检查点的描述**，不是闭包。跨刷新后不重跑丢失的回调，而是按相位重建一个稳定待办：

| phase | 含义 | 刷新后重建为 |
|---|---|---|
| `map` | 地图上等玩家选节点 | 回到地图，avail 可点 |
| `battle` | 战斗中（可能已拼一半） | 回到战斗页，**精确半词**：字母盘逐位相同、不回满、不重抽词 |
| `reward` | 已赢，奖励卡已展开或待展开 | 回到待领奖。**金币与击杀在 winFight 时已入账**，不再发一次 |
| `encounter` | 事件/营火/商店已展开，未选择 | 按快照里的选项描述**原样重建**，不重新 roll |
| `encounter-done` | 选择已生效，等推进 | 只补「推进到下一层」这一个待办，**绝不重跑选项函数** |
| `ending` | 这一局已打完，只差收尾 | 只补「生成纪念卡 + 显示结算」这一次。**不再 `finishNode`、不再 `registerRunWin`** |

### 具体到几个危险窗口

- **胜利后 900ms 才弹奖励面板**：金币与击杀在 `winFight` 里就入账了，相位也在那一刻切成 `reward`，快照里带的是**已经 roll 好**的那批卡（见下一条），所以刷新后回到待领奖，不会二次发金币、也不会换一批卡。
- **奖励卡面在胜利那一刻就 roll 完**（`rollBattleRewards`），展示只是延迟 900ms 画出来（`showRolledRewards`）。以前是「先存空卡面、900ms 后再 roll」，玩家在这段空窗里暂停或刷新就会拿到**另一批**卡 —— 白嫖遗物、换一批道具。现在快照里带的就是玩家马上会看到的那一批。

### `ending`：已经打完的那一局

BOSS 胜利 / BOSS 战败 / 普通战败都在「结算完成、结算屏还没出现」这段延迟里切到 `ending`，并把 `outcome`（赢 / 输）写进快照。玩家在这段窗口里暂停或刷新，恢复时只补一次收尾：

- **不重跑 `finishNode`** —— `battle.finished` 早已为真，重跑也只会拿到 `'ignored'`。
- **不再 `registerRunWin`** —— 通关数在 `finishBattleNode` 那一刻就记过了。
- **纪念卡只生成一张** —— `endRunProgress` 的 `run.reward` 判据负责去重。

`ending` 相位在解码面里**优先于其它一切判定**：奖励卡是否已领（`rewardTaken`）在这条路径上毫无意义，因为这一局已经结束。

战败走 `lifecycle.scheduleRun(..., 800)` 而不是裸 `setTimeout`：这段延迟才能被暂停真正冻结，玩家继续后才结算。战败时 `B.myHp` 会被夹到 0 —— 致命一击会把它扣成负数，而快照口径是 `[0, maxhp]`，不夹的话「刚输掉就暂停」会被判为损坏。
- **营火/事件选完后 900~1100ms 才推进**：副作用（回血、给遗物）已经生效，快照只记 `chosenId`。恢复时只补「推进」这一个待办，不会再加一次血。
- **商店**：可重复购买。购买扣钱发货都在点击当下完成，快照带着已扣钱的 `G`。刷新后回到同一屏商店（库存不重 roll），钱已经扣过，不会免费重买。**「离开」也是一个检查点**：`chosenId` 必须在 `setPhase(ENCOUNTER_DONE)` **之前**发布 —— 因为 `advance()` 有 400ms 双击去重窗口（快速 `advance→shop→leave` 正好落在这里），`locked` 时相位停在 `encounter-done`；这一刻若描述里没有 `chosenId`，codec 的 `needChoice` 判据会把快照判成 `invalid`，刷新后整局丢失。`advance()` 的 `locked` 分支因此也提交一次。
- **奖励卡**：`reopenEncounter` 按快照里的卡面 ID 逐张映射回**带 fn 的真实选项**，展示字段用快照里那一版。映射不上的 ID 一律跳过——宁可少一张卡，也不得凭空执行未知动作。

> 事件/商店/营火的遗物候选表在恢复路径上按 ID **全量铺开**（而不是重新 `pick` 一个）：快照记的是当时那一张，重新 pick 会得到别的 ID，于是那张卡在恢复后凭空消失。

## 暂停：冻结的是状态，不是画面

`src/app/progress.js` 是「谁能改状态」的唯一闸门。暂停期间下列入口一律返回 `false`，且**一个字节都不动状态**：

输入字母、键盘打字、退格、道具、提示、跳过、逃跑、地图节点、事件/营火/商店选项、领奖、推进层数、结算。

这不是 CSS 遮罩：暂停屏是一整屏（战斗页连同它的按钮都不在文档流里），但即便绕过 UI 直接调这些入口，闸门照样挡住。

事件 / 营火 / 商店 / 奖励的**按钮回调**也各自问同一个闸门（`ports.canAct`）。暂停屏挡得住点击，挡不住玩家手里那个**暂停前的按钮引用**再 `dispatchEvent` 一次 —— 以前这些回调直接调 `o.fn()`，暂停期间点事件选项照样回血、照样领遗物。


### 延迟任务

`createLifecycle` 的 `pause()` 把在途任务连同**剩余时间**一起冻结（不执行、也不丢弃），`resume()` 按剩余时间重新挂上。所以「胜利后 900ms 弹奖励」这类任务在暂停期间不会偷偷跑掉，继续时也只补一次。

新开一轮 / 放弃会 `resetRun()` 取消全部旧队列，迟到的回调被 epoch 检查丢弃。

三条容易被忽略的不变量：

1. **迟到回调不重复入队。** `clearTimeout` 只保证「还没跑就别跑」—— 已经排进浏览器事件队列的回调照样会来。`fire()` 必须检查自己还在不在 `pending` 里，否则同一个待办会在 `frozen` 里出现两次，`resume` 后跑两遍（结算、发奖、推进全部翻倍）。
2. **`resetBattle()` 只取消战斗级待办。** run 级待办（BOSS 收尾 700ms、战败 800ms 结算）必须活着 —— 换一场战斗就把它们清掉，那一局再也不会结算。
3. **`resetRun()` 清掉暂停标记。** 否则玩家从主页开新局时，上一次暂停留下的冻结会让新排期的任务直接掉进 `frozen` 再也跑不起来。


跨刷新无法保留闭包，所以跨刷新的重建由上面的相位表负责。

## 恢复不是新建

恢复路径**不**调 `createRun`、**不** `registerRunStart`(+1)、**不** `applyRelicInit`、**不**重复记掌握、**不**重发奖励。`run.countedStart` / `run.clearedRun` 从快照原样带回，天然占住计数名额。

英雄来自快照的 `run.heroId`，不是主页当前选择。

`run.advAt` 不跨刷新继承：`advanceRun` 有 400ms 双击去重窗口，带着旧时间戳回来会把玩家的第一下点击吃掉。

## 拒绝面

非法引用、乱 nodeID、脏数值、不支持的 `schemaVersion` 一律 **fail closed**：不执行、不建出半吊子状态。

- `version` → 提示「来自更新版本，无法恢复」
- `invalid` → 提示「已损坏，无法恢复」

两种情况都**保留存档原文**，包括那份解不开的快照本身。主页仍然显示入口（标为「远征进度已损坏 / 无法恢复」），玩家确认后才丢弃；掌握记录、自定义词库、纪念卡和未知字段一概不动，历史 totals 也不回填。

## 降级

| 情况 | 行为 |
|---|---|
| 没有 localStorage（隐私模式 / 被 CSP 挡） | `commit` 报 `unavailable`，暂停屏明说「本次进度只在这一页有效」，**玩法照常可玩** |
| 写入抛异常（配额满） | 报 `failed`，同样明说没存上；内存里的 DB 恢复原样，不留半份 |
| 存档不是合法 JSON | `peek` 静默降级为 `none` |
| 快照在提交前自检不过 | `commit` 拒绝写入并回报原因，暂停屏显示「没存上」，玩法照常可玩 |

自检不过分两种原因，**提示语必须分开**：`invalid` 是「当前状态解不开（内容不符存档格式）」，`version` 是「当前状态来自更新版本」—— 都不是存储空间问题，说成「空间可能已满」会把玩家引到完全错误的排查方向。两者都只提示、不谎称已保存。

绝不谎称保存成功。同理，**清档 / 丢弃 / 放弃**只有真删掉了才说成功：写失败时如实说「没能删除」，绝不紧接一句「已丢弃」让玩家以为存档干净了。

## 后台 / 前台

`visibilitychange`（hidden）与 `pagehide` 走同一条安全路径：保存一次 → 进入暂停屏 → `TTS.stop()` → 挂起 AudioContext。

回前台**不自动继续**：玩家面对的仍是暂停屏，必须自己点「继续远征」。所以刷新回来不会一撞上敌人或听见语音。AudioContext 的 `resume()` 挂在玩家的手势上（浏览器硬性要求），缺 API 时全部静默。

当前没有「定时自动攻击」这类敌人行为，所以后台没有需要冻结的伤害结算；`docs/product-backlog.md` 的任务 13 引入攻击状态机后，应复用这里的 `lifecycle.pause()` 与闸门。

## 返回主页 ≠ 放弃远征

暂停屏的「返回主页」**不丢进度**：这一局留在内存里继续暂停，快照照旧落盘，主页仍显示「继续远征」。真正丢掉只有「放弃这次远征」和结算。

- **绝不 resume**：resume 会把在途回调重新挂上，玩家待在主页时那一局就会自己往前走（推进层数、结算），回来时局面已经变了。
- **绝不清内存**：没有存储的设备上，内存里这一份就是唯一那一份。
- 同页点「继续远征」优先走**内存恢复**（`source: 'memory'`）：原样回到离开时那一屏，不重建界面、不重排队列。重建会把卡片的 `_used` 清掉（同一个回血能被点两次），冻结中的旧队列还在，重建还会让同一个待办跑两遍。**只有真刷新才走编解码恢复。**
- 同页恢复**不重建事件/营火/商店/奖励**的 DOM —— 它们还在原样，`ENCOUNTER_DONE`（已选完等推进）更是必须留着，冻结中的那个推进在 `resume` 后正好补上一次。
- 返回主页后新开远征必须先确认放弃；确认前那一局与快照都原样保留。**正在玩**的一局仍然挡住连点（闸门只对「暂停中返回主页」的那一局放行）。
- 没有存储时主页仍然给出入口（`heldInMemory: true`、`savedAt: null`）—— 如实说「还在这一页里，关掉页面就会丢失」，**绝不显示成「保存于 null」**（那看起来像一个坏掉的时间戳）。


## 已结算的一局不再被存

`run.result` 是布尔值即代表这一局已结算。此后**一律拒绝写快照**：`currentEnvelope`、暂停、切后台、`pagehide` 全部返回「已结束」。否则刷新会把「已经打完」的一局复活成死局（结算屏上一片血，却还能接着打）。结算屏上的 `pagehide` 也不许把暂停屏抢回来。


## 保存一致性：一个动作 = 一次提交

`saveDB()` **不再**直接 `storage.save(DB)`。整词答对时 `creditWord` 会调它，可那一刻 `wordsDone` / 整词伤害 / 敌人血量都还没更新 —— 直接落盘就会把「新掌握的词」和「上一帧的战斗」写在一起，暂停/刷新都读得到中间态。

现在有两个提交判据，缺一不可：

- **`saveDB()` 只标脏**（`dbDirty`）。学习 DB 变了、但当前状态还没稳定时用它。
- **受闸门动作跑完 → `commit(force=true)`，无条件把当前快照写下去。** 判据是「这个动作结束了」，**不是**「学习记录碰巧脏了」。

第二条是必须的：`enterNode`（进战斗）、半词输入、提示、道具、跳过、逃跑、商店/营火/事件按钮、领奖、语音开关这一整批真实动作**根本不调 `saveDB()`**。早期版本只在 `dbDirty` 为真时提交，于是这批进度只活在内存里 —— 玩家刷新一次就退回上一个动作，而界面上完全看不出任何异常。

事务用 `mutationDepth` 计数支持**嵌套**：`enterNode → startFight`、领奖 → `finishNode → advance`、战败 → `markEnding` 这些内层收尾都不许提前写盘（否则会写出「坏相位」的中间快照），只有最外层 `depth` 归零才提交一次。`advance()` 的 `'locked'` 分支（400ms 双击去重窗口）也提交 —— 此时调用方已经发布了 `chosenId` 并切到 `encounter-done`，盘上必须有一份**合法**的快照，否则刷新后整局被判损坏。

没有进行中的远征时（音量、字母盘模式、导入词表、语音开关）退化成纯 DB 写；存档里那份解不开的 `activeRun` 属于**未知字段**，原样保留，不在这些路径里被清掉。

新局是显式的例外：`newRun()` 完整建好 `G` 与相位之后才提交，快照必须是一局**可玩**的远征，不能是「次数已 +1、地图还没建」的那一帧。

`ending` 相位同理必须无条件落盘（通关数与纪念卡在 `finishBattleNode` 那一刻已改完），但它发生在领奖事务内部时会自动延期到最外层，不会写出中间态。


## 结束：一次写完成结算与清快照

结算拆成两半：`settleRun(win)`（内存侧）改 DB、生成纪念卡、画结算屏但**不落盘**；`endRunNow(win)`（控制器内）走闸门 → `settleRun` → `store.clear(DB)`，后者是**同一次** `storage.save`，同时写入「新 totals + 纪念卡」与「快照已删除」。

先清后结算、或分两次写，都会留下「奖励已发、快照还在」的窗口：刷新后那一局会被再结算一次，纪念卡、通关数、金币全部翻倍。单元测试直接断言写次数（1 次）。

清档（`resetProgress`）走同一条路。清不掉时**如实提示**「没能删除存档里的远征进度」，绝不谎称丢成功 —— 否则玩家刷新后发现那一局还在。

## 一次性资源的跨暂停

影分身额度 `G.ghostUsed` 是 **run 级**事实，存在 `run` 上而不是战斗上，所以跨暂停、跨刷新、换战斗都不会重置。E2E 里有一条专门守它的用例。

## 已知边界

- **没有后台自动保存计时器**：切后台 / 关闭页面 / 显式暂停仍然各存一次，但**每个真实动作本身就已经在落盘**（见上面「一个动作 = 一次提交」），所以不存在「只靠后台那一下才存上」的窗口。剩下的边界只有一个：玩家直接杀进程、且浏览器完全没派发 `pagehide`/`visibilitychange`（例如强杀标签页进程）时，那一下的进度会丢。
- **倒计时类机制还没接入**：目前游戏里没有敌人定时攻击，倒计时暂停/续计只做到了 `lifecycle` 的冻结语义（剩余时间保留），没有独立的「剩余秒数」字段。任务 10/13 落地时需要补上。
- **奖励卡的 900ms 动画不跨刷新保留**：刷新后直接进待领奖面板，不重播大招动画。这是刻意的：重播会让人以为能再拿一次。
- **恢复路径的展示字段来自存档**：快照里的 `ic` / `t` / `d` / `tip` 是不可信输入，恢复时**只在渲染边界**（`cardButton(o, {untrusted:true})`）转义后再进 `innerHTML`（普通新开路径的模板一个字都不动）。转义后的串**绝不写回** opts / `publish()`：否则 `reopen → publish → reopen` 会把 `&` 再转义一次，界面上出现 `&amp;lt;` 这种实体堆叠，存档里的原文也被污染。选项 ID 映射不上时明确告诉玩家（部分跳过 / 全部失败则退回地图），不静默把他丢回地图。
- **`__gameTest` 探针只在 DEV + 测试预置标记下出现**，生产编译完全移除（见 `tests/build/production.test.js`）。
