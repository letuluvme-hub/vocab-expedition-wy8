# 学得好 = 打得好：远征玩法重做规划

> **这份文档是什么**：自由远征（roguelite 战斗）玩法重做的规划书，按阶段拆成可独立交付、可独立试玩验证的任务。
> 每个阶段写了**规则 / 候选数值 / 改动位置 / 存档 / 测试 / 试玩过关标准**，可以直接交给实现 agent。
>
> **范围**：只管「背单词打怪」这条主循环。每日默写模块不在本规划内，本规划也不改它。
>
> **状态（2026-10-03）**：P0 已上线（#25、#27）。P3 中的「选卡出招」已经以 `docs/feature-word-choice.md` 的形式提前上线（#28），数值冻结也已在 #28 中解除。P1–P2 尚未实施。所有数值都是**候选起点**，必须由真人试玩定标。
> 做 P1 时注意：#28 的选词卡显示「伤害预览」，用的是旧的 `hitDmg` / `wordDmg`，必须随整词结算的新公式一起改。
>
> **编写基线**：`main` @ `60c7afc`（2026-10-03）。

## 0. 为什么要重做：现状诊断（用真实公式模拟得出）

### 0.1 「学」和「打」是两本互不相通的账

- **学**：整词拼完就记「学会」，用了提示、听了读音也算（`src/domain/learning.js` 的 `creditWordProgress`）。
- **打**：伤害 / 血量 / 连击数字。

两本账互不影响：拼得好不会让你更强，构筑也不改变你怎么拼。

### 0.2 伤害对结果没有影响 —— 每场恒定 3 个词

用 `foeHpMax` + `hitDmg` + `wordDmg` 模拟完美拼写击杀中性普通怪：

| 楼层 | 怪物血量 | 无构筑 | 带连击徽章 | 幸运儿（连击 -10%） |
|---|---|---|---|---|
| 1 | 392 | 3 词 | 3 词 | 3 词 |
| 5 | 580 | 3 词 | 3 词 | 3 词 |
| 9 | 768 | 3 词 | 3 词 | 3 词 |

原因有两个：
- 怪物血量公式把玩家的连击率传了进去（`foe-stats.js` 的 `comboRate` 参数），**玩家变强，怪物跟着变硬**。
- 只有整词能击杀，零碎的伤害差跨不过「再拼一个词」这道坎。

**连大招 ×1.5 也不改变词数**（模拟结果仍是 3 词）：单字母伤害约占每词伤害的 60%，并且在词拼完之前就已经打出去了。
→ 只给大招加倍率，「拼得好」是感受不到的。这是第 2 节 P1 把伤害改成**整词结算**的直接依据。

### 0.3 生命值跨场不消耗 —— 回血类内容全部失效

战后奖励「恢复生命」的公式是 `12 + 怪物血上限 × 12%`（`encounters.js` 的 `rollBattleRewards`），用的是**怪物的血量**：

| 楼层 | 战后回血 | 占玩家 70 血上限 |
|---|---|---|
| 1 | 59 | 84% |
| 5 | 82 | 117% |
| 9 | 104 | 148% |

每场都能回满，生命只在单场内部有意义。治愈师、游侠、永动电池、锻造台、吸血獠牙、铁血循环、营火休息都在解决不存在的问题。

### 0.4 惩罚逼人不去回忆

- 错一个字母扣 12 血（首领 16），上限只有 70。孩子最合理的选择是先按提示。
- 每场 3 次免费提示，每场约 3 个词，相当于每词白送一次提示。
- 字母盘只放「答案字母 + 少量干扰字母」，很多时候是认字母拼图，不是回忆单词。
- 怪物蓄力被**任意字母**打断（`combat.js` 的 `notifyAttempt` 在答错分支也会调用），乱按也能防住攻击。

### 0.5 角色和装备只改数字，而且互相压制

- 一场约 21 个正确字母：游侠回 21 血，治愈师回 6 血，游侠全面压制治愈师。
- 学者和战士互为镜像（提示 ↔ 生命）。生命过剩，所以学者压制战士。
- 幸运儿：+15 金约等于半场战斗的金币，-10% 连击不改变击杀词数，两边加起来约等于 0。
- 扫除术是负价值：字母盘每个词都会重置，而且只有「不在这个词里」的字母才会被标错。扫除术等于把确定错误的字母重新放出来。

## 1. 设计原则（之后每个改动都拿来对照）

1. **拼写质量是唯一的硬通货**。伤害、金币、奖励都从「这个词拼得多干净」里来。
2. **奖励成功，而不是惩罚失败**。出错的主要代价是「失去完美」，不是扣一大口血。
3. **错误是未来的宝箱**。拼错的词会再出现，之后拼对拿的奖励比一次就拼对还多。
4. **构筑改变「怎么拼」，不改「数字多大」**。每个角色、遗物和怪物都必须改变某个拼写行为或拼写决策。
5. **赌注下注前可见**。玩家按提示之前，就要知道「这个词不再完美」。
6. **难度自选，但躲不掉**。可以先挑简单的打，但精英和首领会把难词、错词端上来。

## 3. P0 · 埋点（先拿基线）

**目的**：没有改动前的数据，P1 的试玩结论就只是感觉。P0 不改任何规则。

### 记录什么（本局，跟着快照走）

`run.qStats = { words, perfect, hintWords, wrongWords, hintsUsed, wrongLetters, listenUsed }`

- `perfect`：按 P1 的「完美」定义统计（不出错、不用提示、不听读音），但**只统计，不发奖励**。
- 词级标记放在 `B.wordQ = { wrong:0, hint:0, listen:0 }`，换词时（`runtime.js` 的 `nextWord`、`startFight`）重置；整词完成时汇总进 `run.qStats`。

### 展示

- 结算页（`src/ui/screens/over.js`）多一行：「完美 7/12 · 平均每词提示 0.8 · 每词错字母 1.2」。
- `DB.playLog`：最近 20 局的 `{ endedAt, hero, unit, qStats, win }`，数组且有上限，属于未知字段兼容范围。家长可以截图对比。

### 存档

- `encodeBattle` 增加可选字段 `wordQ`，`run` 增加可选字段 `qStats`，写法和 `foeAttack` 一样：合法才写，缺失回落成 0，脏值不写。
- 旧快照恢复时 `wordQ` 缺失：**按「已不完美」处理**（宁可少发也不多发），P0 阶段只影响统计。

### 测试

- 单元：`wordQ` 在答错、提示、听读音时各自 +1；换词清零；暂停刷新之后不重置也不重复计数。
- 变异：把「听读音计入 listen」删掉，对应断言必须变红。

## 4. P1 · 拼写质量决定伤害（核心）

### 4.1 拼写质量三档

整词完成的那一刻，按本词的 `B.wordQ` 判档：

| 档位 | 条件 | 伤害倍率 | 额外奖励 |
|---|---|---|---|
| ✨ 完美 | `wrong = hint = listen = 0` | ×1.5 | +3 金币；「完美连胜」+1 |
| ✅ 合格 | 有错或有提示，且揭示字母 < 词长一半 | ×1.0 | — |
| 🆘 求助 | 揭示字母 ≥ 词长一半（提示 / 透视 / 预知累计） | ×0.5 | — |

- 位置错（字母在词里但顺序不对）也计为 `wrong`。
- 「完美连胜」复用现有的 `B.wordStreak` 和 `finTier()`（每级 +12%，上限 +48%），但**只有完美词才 +1**，非完美词清零。

### 4.2 伤害改为整词结算（关键改动）

**现状**：每个正确字母都打伤害，大招只占约 40%。质量倍率只乘在大招上，玩家感受不到（见 0.2）。

**改为**：
- 正确字母**不再造成伤害**，改成「咒语蓄能」：词卡下方的蓄能条每输入一个字母填一格。还是完美时蓄能条是**金色**，一出错、一用提示就变**银色**。这一条同时满足原则 5（赌注下注前可见）。
- 伤害只在整词完成时结算一次：`整词伤害 = U(floor) × 质量倍率 × finTier × 道具倍率 × 怪种倍率`。
- `U(floor)` = 「一个合格词」的伤害单位，沿用现有 `perWord` 公式，但 `comboRate` **固定为 0.1**，不再读玩家构筑。这样怪物不再跟着玩家变硬，数字的量级和现在接近。
- 怪物血量以「合格词」为单位：普通 3U、精英 4U、首领 5U；怪种倍率 0.65–1.25 保留（只对普通怪生效）。

**预期手感**（候选，待试玩）：

| 怪物 | 全合格 | 全完美 | 全求助 |
|---|---|---|---|
| 普通（中性） | 3 词 | 2 词 | 6 词 |
| 精英 | 4 词 | 3 词 | 8 词 |
| 首领 | 5 词 | 4 词 | 10 词 |

拼得干净，战斗明显变短、金币更多。这就是「学得好 = 打得好」最直接的形式。

**不变的底线**：只有整词能击杀；半词不算学会；整词只记一次（`battle-rules.js` 的 `applyDamage` / `canFinishFight` 不动）。

### 4.3 错误轻罚，威胁交给怪物

| 项目 | 现在 | P1 候选 |
|---|---|---|
| 错字母（不在词里） | 12 / 首领 16 | **4 / 首领 6** |
| 顺序错 | 6 / 首领 8 | **2 / 首领 3** |
| 怪物蓄力伤害 | 4 / 6 / 8 | **6 / 9 / 12** |
| 谁能打断蓄力 | 任意被接受的字母 | **只有正确字母** |

- 结果是：会的词挡得住攻击，不会的词就挨打或者花提示。代价来自「不会」，而不是来自「试错」。
- 蓄力窗口（idle / telegraph / recover）保持不变，`round-difficulty.js` 的思考窗口下限也不动。
- 改动点：`combat.js` 答错分支删掉 `notifyAttempt()`，两处 `hurtPlayer` 的数值改用 `balance.js` 里新的常量；`FOE_ATTACK.damage` 改值。

### 4.4 回血公式修正

- 战后「恢复生命」从 `12 + enMax × 0.12` 改为 `round(G.maxhp × 0.3)`。实时路径和暂停恢复路径两处都要改（`encounters.js` 约 422 行、约 584 行）。
- **旧快照兼容**：改动前存下的战后奖励卡，卡面写的是旧数值（例如「回复 59 点生命」）。恢复时必须按卡面兑现，不能刷新一次就变成另一个数，做法同 `LEGACY_RELIC_SHOP_PRICE`。
- 营火、泉水等固定数值暂不动，P1 试玩后再看。

### 4.5 被 P1 波及、必须同步改写的旧内容

字母不再造成伤害之后，下面这些内容的文案和效果会失真。装备面板契约要求 `d` 文案和实际结算一致，所以必须在 P1 里同步做**最小改写**（完整重做留到 P3）：

| 内容 | P1 的最小改写 |
|---|---|
| 遗物 连击徽章 `combo` | 「完美词伤害 +30%」 |
| 遗物 专注头环 `focus` | 「出错时完美连胜保留一半（不清零）」 |
| 道具 怒火 `rage` | 「下一个整词伤害 ×2，并清空完美连胜」 |
| 道具 寒冰 `freeze` | 「冻结怪物攻击直到这个词完成」，**不再减伤**，也不破坏完美（不提供答案信息） |
| 道具 连锁闪电 `chain` | 退出商店和掉落池；背包里已有的可以用，效果改为「完美连胜 +1」 |
| 怪物 石化词素 | 「合格 / 求助词伤害 ×0.75，完美词 ×1.5」：硬壳只有完美能砸开 |
| 连击 `dmgBonus`（每 5 连击加伤） | 删除（连击里程碑 6/10/12 照常发放，连击仍然逐字母计数） |

`tests/unit/extraction.test.js` 钉住了遗物和道具的文案，这里属于**有意漂移**：更新断言，并在 PR 描述里逐条列出。

### 4.6 UI

- 词卡上的金色 / 银色蓄能条。
- 提示按钮和听读音按钮上显示小字「用后不再完美」（只在当前词仍然完美时显示）。
- 整词完成时根据档位飘字：「✨ 完美！」「✅」「🆘」；完美时额外飘「+3 💰」。
- 新增样式只能放进新样式表，冻结的 7 张 CSS 不动（见 `tests/unit/styles.test.js`）。

### 4.7 测试

- 单元：三档判定的边界（揭示数正好等于词长一半、含连字符和空格的短语）；`finTier` 只被完美词推高；怪物血量不再随连击徽章变化（反向断言：有无 `combo` 遗物时 `hpMax` 相等）。
- 单元：答错不再打断蓄力，正确字母打断；错字母 4 点先扣护盾再扣生命。
- 变异：把完美倍率改成 1.0，「全完美普通怪 2 词击杀」的断言必须变红。
- e2e：完整打一场，看到金色蓄能条变银、档位飘字、2 词击杀。

### 4.8 试玩过关标准

对比 P0 基线，同一个孩子玩 3 局：
1. **每词提示数下降**（这是 P1 最核心的信号）；
2. 孩子出现「这个我想自己拼」「刚才那个不算完美」这类行为或说法；
3. 没有出现「被怪打得太疼不想玩」。如果出现，先调蓄力伤害和窗口，不改质量规则。

1 和 2 都不成立，就说明问题在更上游，**停下来重新讨论，不进 P2**。

## 5. P2 · 错词回炉与错词之王

### 5.1 「学会」的定义（需要你拍板，见第 9 节 D1）

建议：**从 P2 起，只有完美拼对才记「学会」**（写入 `DB.mastered`、计入 `run.done`）。旧的 `mastered` 记录保留，不删也不改。

### 5.2 错词回炉

- 合格或求助完成的词：不进 `run.done`，进 `run.wrong`（这个队列已经存在，`drawWord` 会优先抽它），并要求中间**至少隔 2 个其他词**再出现。
- 同一个词本局最多回炉 2 次。第 3 次仍不完美时，计入 `run.done` 并标记「待复习」（写入现有的 `DB.reviewQueue`），保证单元一定能打完，不会卡死。
- 改动点：`domain/word-selection.js` 的 `drawWord`（加间隔），`domain/learning.js`（新增「非完美完成」记账函数），`runtime.js` 的 `creditWord` 接线。

### 5.3 攻克

- `run.wrong` 里的词被完美拼对，就是「攻克」：专属动画、+10 金币、回 5 血，记入 `run.conquered`。
- 设计意图：一个拼错的词，之后拼对的收益**高于**一次就拼对。出错从失败变成埋下一个宝箱。

### 5.4 错词之王（首领）

- 首领战的 5 个词优先从本局「曾经出过错的词」里抽（包括已攻克的），不够再从未完成词里补。
- 首领开场台词点名：「你今天拼错的 N 个词，都在我这里。」
- 学习意义：同一局里的间隔复习。叙事意义：打败自己的错误。
- 不变：逃跑、跳过首领都不算通关（`SKIP_HP_COST`、影分身规则不动）。

### 5.5 测试与过关标准

- 单元：回炉间隔、回炉上限、攻克只发一次、首领抽词优先级、暂停刷新后 `run.conquered` 不丢也不重复。
- 试玩：观察孩子拼错之后的反应。目标是看到「等它再出来」的期待，而不是放弃这个词。

## 6. P3 · 构筑重做

### 6.1 角色：6 种学习风格（保留现有 6 个 id 和形象）

| id | 新名称 · 定位 | 能力 | 代价 |
|---|---|---|---|
| `warrior` | 战士 · 稳扎稳打（新手） | 每个词第一次出错不破完美 | 完美倍率 ×1.3（不是 1.5） |
| `scholar` | 学者 · 温故知新（复习） | 攻克奖励 ×2；首领战中回炉词伤害 +50% | 首次见到的词完美倍率 ×1.3 |
| `scout` | 探险家 · 开拓（新词） | 本局第一次见到的词完美拼对，金币 ×2 | 干扰字母 +1 |
| `ranger` | 游侠 · 速攻（流利度） | 在怪物蓄力期间完成整词：打断并追加 50% 伤害 | 怪物 idle 窗口 -1 秒（不低于下限） |
| `lucky` | 幸运儿 · 冒险（挑战） | 选卡出招时多 1 张高难卡；高难卡奖励 +50% | 每场提示 -1 |
| `healer` | 治愈师 · 听觉型（拼读） | 听读音不破完美；每次攻克回 10 血 | 完美倍率 ×1.3 |

- 每个角色改变的是一种**拼写决策**（敢不敢试错、要不要复习、挑哪张卡、要不要拼快、要不要听），不是一个数字。
- 存档里 `DB.hero` 的 id 不变，旧存档直接沿用。

### 6.2 遗物：由学习事件触发（保留 12 个 id，改效果）

| id | 现在 | 改为 |
|---|---|---|
| `hint` 提示水晶 | 每场多 2 次提示 | 保留（安全网，但用了会破完美） |
| `shield` 护盾符文 | 开局 15 护盾 | 保留（生命开始消耗之后护盾有意义了） |
| `combo` 连击徽章 | （P1）完美词 +30% | **连胜火种**：完美连胜到 3，下一个大招 ×2 |
| `purse` 聚宝盆 | 胜利 +25 金 | 保留 |
| `thorn` 荆棘护符 | 答错反弹伤害（奖励了错误，违背原则 2） | **反击之刺**：用正确字母打断蓄力时，对怪物造成 0.3U 伤害 |
| `battery` 永动电池 | 每层回 8 血 | **复苏电池**：每攻克一个词回 6 血 |
| `lucky` 幸运草 | 首次答错不掉血 | **幸运草**：每场第一个错误不破完美 |
| `scholar` 学者之书 | 胜利掉先知卡（帮你揭示答案） | **复仇之书**：攻克时额外获得「词长 × 2」金币 |
| `forge` 锻造台 | 营火回 20 | **主题共鸣**：连续完美拼对 2 个同主题（`th`）的词，下一词伤害 ×2 |
| `ghost` 影分身 | 免费跳过一次 | 保留 |
| `greed` 贪婪之眼 | 金币 +50% | 保留 |
| `focus` 专注头环 | （P1）连胜保留一半 | **长词之刃**：8 个字母以上的词伤害 +50% |
| `prophecy` 预知残卷（传说） | 答错揭示全词 | **蒙眼大师**：盲打模式下的完美词伤害 ×2、金币 ×2 |

- 组合技（`relic-rules.js` 的 4 组）全部删掉，等新遗物试玩稳定后再按新主题补。
- `th`（主题）、`d`（难度）和词长都是词库已有字段，不需要改 259 词的数据。校本词库没有主题时，「主题共鸣」不进奖池。

### 6.3 道具：从 8 个精简到 4 个

保留 **寒冰**（P1 版：冻结攻击、不减伤）、**透视**、**磐石**、**怒火**（P1 版）。
吸血獠牙、连锁闪电、扫除术、贪婪钱币退出商店和掉落池；背包里已有的照常可用。新局初始背包从「吸血獠牙 ×2」改为「寒冰 ×1」。

### 6.4 盲打模式

- 每个词输入第一个字母之前，可以切到完整 26 键（复用每日默写已有的 `ui/components/dictation-keyboard.js`），不给字母盘。
- 盲打完成的词：伤害和金币 ×1.5，可以和完美叠加。
- 字母盘是辅助轮，盲打是真回忆，由孩子自己决定要不要拆辅助轮。

### 6.5 选卡出招

- 每个词出现前给 2 张中文卡：一张来自 `d` 较低或较短的词，一张来自 `d` 较高或较长的词。高难卡伤害 ×1.3、金币 +2。
- 没选的词留在池子里；精英和首领不给选，直接出难词或错词。
- 这是 P3 里 UI 改动最大的一项，可以拆成独立 PR，放在最后做。

### 6.6 怪物：按拼法区分（`balance.js` 的 `FOE_TRAITS`，按怪名索引，不改存档）

| 怪物 | 机制 |
|---|---|
| 石化词素 | P1 版：只有完美能砸开 |
| 拼写幽灵 | 不给字母盘，强制盲打；击败奖励 ×1.5 |
| 词形旋风 | 每输入一个字母，字母盘重新打乱 |
| 冰封词灵 | 字母盘冻住，听一次读音才解冻；在这只怪面前听读音不破完美 |
| 歧义章鱼 | 中文释义只显示前半（`z` 中分号之前的部分） |
| 精英（全部） | 一次给 2 个词，都拼完才能造成伤害（就是 backlog 清单 12） |

### 6.7 试玩过关标准

让孩子用 3 个不同角色各玩 1 局，再问「你最喜欢哪个、为什么」。回答必须能说出**打法上的区别**（「战士可以放心试」「探险家要拼新词」），而不只是「血多」。

## 7. P4 · 局外成长与结算

### 7.1 单词星级

`DB.wordStars = { [词key]: { s: 1..3, at: 时间戳 } }`（新字段，未知字段兼容）：
- ★1：第一次完美拼对。
- ★2：距离 ★1 至少 1 天，在另一局里再次完美拼对。
- ★3：距离 ★2 至少 3 天，再次完美拼对。
- **星级只升不降**（正向原则）。到期没复习不扣星，只是让这个词变成「金色怪」。

### 7.2 金色复习怪

- 星级低于 3、且已到复习间隔的词，抽到时用金色怪物出场：完美拼对金币 ×2，并且升星。
- 间隔复习被包装成刷宝，不依赖每日默写模块。

### 7.3 墨水与解锁

- 局外货币「墨水」**只来自学习**：升到 ★1 / ★2 / ★3 分别 +1 / +2 / +3，攻克 +1；击杀不给墨水。
- 用墨水解锁：角色（新用户默认开放战士、学者、探险家）、遗物进入奖池（默认开放 8 件）、外观。
- 老用户：已经能选的角色和遗物全部保留，不回收。

### 7.4 结算页

- 主角从「层数和击杀」换成学习成果：
  - **评级**：按完美率给 S（≥80%）/ A（≥60%）/ B（≥40%）/ C；
  - **本局攻克**：列出攻克的词；
  - **升星**：列出升星的词，以及获得的墨水。
- **战败也展示并保留**升星、攻克和墨水，进度永远不会因为输了而丢。
- 顺带解决 `optimization-plan-2026-10.md` C1 的「复习本单元 / 继续本单元」歧义（按该文方案 A 改文案）。

### 7.5 和现有「知识成长」（每 20 词 +1 血上限）的关系

它加的是生命值，在 P1 回血修正之后才有意义。建议在 P4 改成「墨水解锁」，或者保留但不再宣传。见 D3。

### 8.2 正式接入需要的数据

|---|---|---|---|

| 音标、例句、词性 | — | 可选 | 先存起来，以后可以做「例句填空」怪 |

**材料可以是什么格式**：Excel / CSV 最好；Word、PDF、拍照也可以，由我转录，但需要你校对一遍。转录结果只进新的 `src/data/books/<校本id>/`，**不碰现有 259 词**。

## 10. 风险

1. **好不好玩只能靠真人验证**。以上全部是纸面设计，所以每个阶段都设了试玩关卡。
2. **计时压力**：错误变轻之后，怪物蓄力成了主要威胁，对慢一点的孩子可能有压力。兜底方案是加一个「练习难度」：关掉怪物攻击，奖励减半。
3. **选卡可能让人躲难词**：靠精英和首领强制出难词兜底，效果要观察。
4. **工程量**：`runtime.js` 里还有闭包状态，单测 1000 多条，约束多。P1 已经会碰到伤害、怪物血量、战斗、遗物文案、存档快照五处，必须严格按 `AGENTS.md` 先写失败测试再实现，结算顺序（最后一击、荆棘、回血、掌握记账、`setTimeout`）要有专门的回归测试。
5. **和 backlog 的重叠**：P3 覆盖清单 11（角色平衡）和清单 12（多词怪）；清单 10（逐轮递增）仍然独立做，但它的血量倍率要改成作用在「U × 词数」上；清单 14（结算动画）可以直接用 P1 的档位飘字作为触发点。
