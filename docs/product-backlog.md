# 重构上线后的玩法与学习改进

## 执行边界

先完成当前结构重构、合并 PR 与线上验收，再开始此清单。禁止为了赶工将下面的玩法改动夹进结构重构，避免无法判断回归来源。每个功能点独立子智能体、限定文件范围，按依赖串行执行；每项先写失败测试，整合者独立验收后才进入下一项。紧密相关的功能可以共享同一已确认接口，但不能多个写入者同时改战斗或存档入口。

本清单记录用户原始需求，并将机制建议标为建议，不把建议当成已实施或已验收。

## 任务清单（逐项验收）

### A. 先堵漏洞，确定战斗终结规则

1. **远征次数与通关次数不对。** 查清现有触发路径：新开远征、继续存档、重复结算、BOSS 逃跑/影分身、下一单元、失败重开。设计唯一计数入口与幂等 ID。建议远征次数只在真正新开一轮时增加，恢复不增加；只有符合本轮完成条件时通关次数增加一次。解锁机制落地后补单元通关和全轮通关的独立语义，不能继续混用同一指标。不能凭空修正既有历史总数。
2. **跳过过强。** 将跳过变成真实有代价的撤退，不能直接算获胜、学会或解锁。用户例子“扣血更多，比如50”暂按固定 50 点生命的候选方案，不等同 50%。实现前结合角色生命上限验证；不足生命时禁止跳过或导致失败，不能用 Math.max(1,...) 让玩家永远不死。BOSS 不允许借跳过通关。
3. **影分身无限使用。** 建议限制为每轮远征仅一次，消耗状态必须跨战斗、跨暂停恢复保存；不能每场重置。仅撤退一关，不算完成该关词汇/怪物击杀。图鉴与战斗按钮同步剩余次数。
4. **击杀必须由完整单词触发。** 单字母伤害/荆棘/道具只能把敌人压到待终结状态，不能提前获胜；最后一个正确字母形成完整词，满足词组门槛后才能击杀结算。测试最后字母、残血、荆棘、连锁与重复输入的唯一结算顺序，保留错误答案不授予掌握记录。

### B. 持久进度与学习主线

5. ~~**保存进度与暂停。**~~ **已实施**（`docs/feature-pause.md`）：版本化快照存进 `wy8a_rogue_v1` 的 `activeRun`，`schemaVersion: 1`。Set 落盘成数组、地图 links 落盘成 nodeID 并在恢复时接回同一批对象，计时器与闭包不落盘而是靠相位检查点重建。暂停冻结所有改状态入口并按剩余时间冻结延迟任务，切后台/关页面安全存盘，回前台不自动继续。恢复不是新建：不加次数、不重跑遗物初始化、不重复发奖。损坏与版本不支持的快照 fail closed 并保留存档原文。**仍未做**：后台周期性自动保存、倒计时剩余秒数的持久化（等清单 13 的攻击状态机）。
6. ~~**单词尽量不重复。**~~ **已实施**（`docs/feature-word-queue.md`）：本轮已完成的词（`run.done`）**绝不**作为候选返回，小词池不再回灌整池（旧的 `if(pool.length<3)` 整池重灌已删）；相同英文的重复词条只有第一条是候选（重复字母仍算一个词条）；错词队列去重且必须仍是未完成词，沿用旧配额「最多占一半」以免 fresh 饿死；避免立刻重复从「随机试 10 次后认命」改成「先剔除上一词再抽」，只剩一个未完成词时仍允许它出现（「尽量」不是跳过）。词池抽干时抽词返回 `null`，`startFight`/`nextWord` 统一进 `PHASE.LEARNING_COMPLETE` 检查点：kills/gold/wins 一律不动、绝不调 `endRun(true)`、怪物血与 run 状态如实写进快照，界面只说「本单元词汇已全部完成」并明说「本轮不算通关」，绝不出现通关/解锁字样。**仍未做**：下一单元的解锁与继承（见第 7 项）、教材/单元/词条稳定 ID 与旧 `mastered` 字符串映射、`run.done` 仍以英文字符串记账。
7. ~~**全部完成 Unit 1 才解锁下一单元，金币物品继续使用。**~~ **已实施**（`docs/feature-campaign.md`）：`src/domain/campaign.js` 纯规则（`unlockProgress` / `canSelectUnit` / `recordUnitComplete` / `transitionNextUnit` / `applyUnitTransition` / `applyUnitSegment`）。解锁只看本单元目标词是否全部**整词**拼对（`mastered` 覆盖，身份 `trim+lower`），不看 `wins`/`best`/纪念卡；连续解锁，旧存档按 `mastered` 保守迁移，绝不凭历史授予全册；自定义词表永远可玩但不解锁。跨单元是**同一轮**：G.id、`countedStart`、`clearedRun`、金币/背包/遗物/影分身额度/学习统计全部继承，只换词池与地图（`floor` 重置、`maxFloor` 不改小），`DB.runs`/`DB.wins`/纪念卡一个都不加。BOSS 胜利与词汇完成分成两个独立事实：词先完成 → 检查点「继续 Unit N+1」；BOSS 先完成但本单元还有词 → 结算屏「继续本单元词汇」（同轮换一段地图继续抽未完成词，不提前解锁、不卡死）。主页锁住的单元写清解锁条件且**不挂回调**，`runtime.newRun()` 另有 `canSelectUnit` 闸门。`run.campaign{startedUnit,segments}` 进快照，旧快照按 `run.unit` 回落。**仍未做**：轮次纪念卡（清单 8）、知识天赋（清单 9）、教材词条稳定 ID 与旧 `mastered` 字符串的正式映射、真机验证。**原需求**： 将零散独立远征变成连续学习轮次：同一轮跨单元保留金币、装备、消耗品和角色。解锁以本单元所有目标词完整正确完成为必要条件，不以单次 BOSS 击杀代替。进度卡说明已完成/剩余；保留已解锁单元的复习入口。旧用户既有学习记录迁移需保守、可解释，不凭空删除或授予全册解锁。
8. ~~**通关卡显示轮次。**~~ **已实施**（`docs/feature-rounds.md`）：真实新开轮编号取计数后 `DB.runs`，持久 `roundId` 与进程诊断 ID 分开；恢复、跨单元不补填或重编号。一轮最多一张纪念卡；本轮完成范围只看 `run.done` 覆盖该单元非空词池，不借历史 `mastered`。已有卡在词汇完成、合法过渡及结束学习前同步同次存盘，不再领奖或改变获得时间。旧卡缺字段显示「旧版记录 · 未记录轮次」「未记录完成范围」，不猜编号或将未知说成未完成。失败、撤退和重复恢复不生成卡。
9. ~~**解锁的单词越多越强。**~~ **已实施**（`docs/feature-mastery-growth.md`）：只计教材掌握身份交集且去重，每20词给新轮+1生命上限、封顶+12，自定义独有词不计。成长开局应用一次并保存快照，恢复、跨单元和本局达到阈值不叠加或回血；旧快照保原上限不补填。主页显示真实进度、下档门槛及新轮生效说明。未改伤害，长期平衡与真机仍待标定。

### C. 难度、角色与怪物规则

10. **每轮怪物能力、伤害、攻击速度递增。** 基于轮次/单元分段配置敌人生命、伤害、攻击间隔与任务词数，设上限与最低思考窗口。依赖暂停计时器和轮次主线；不要单独无上限加速造成无法完成中译英回忆。
11. **角色能力更鲜明且平衡。** 为每个角色明确学习/战斗定位与代价，用同种子/同词库模拟通关率、平均受伤、提示和收益。角色强度不能只凭感觉调。与知识天赋、跳过成本、攻击打断机制共同验证，再单独修改配置/技能。
12. **部分怪物要同时拼对多个词才能结算。** 先定义“同时”：建议采用一个多词挑战组，必须在同一挑战组里完整完成指定词数才允许击杀，不要求在一个输入框混拼。UI 可切换词卡，任何半词不计完成；暂停恢复、提示与错词队列一致。精英/BOSS 用配置门槛，普通怪保持轻量。
13. **怪物更大、有持续数秒的攻击蓄力，输入字母可打断，强怪间隔更短。** 实现 idle -> telegraph -> attack/recover -> defeated 明确状态机，蓄力进度可视化；建议只用有效正确输入打断，避免乱按无限安全，但这是待确认的机制建议，用户原意是“输入字母则可以打断”。暂停/后台必须冻结，不积累回来瞬间多次伤害。尺寸不挤掉手机字母盘/HUD。与10、12共同测试。

### D. 战斗展示与反馈

14. **每个词完成和每个怪物死亡有更有趣的结算动画。** 词完成反馈与怪物击败反馈分开，动画不能阻塞计账或重入领奖，支持 reduced-motion；视觉不遮释义/血条/按钮。依赖4确定唯一触发点、13的 defeated 状态。
15. **字母盘默认键盘布局。** 新用户默认 QWERTY，已存用户明确选过的偏好保留；旧字段缺失时迁移默认，仍支持切换，不丢输入。
16. **声音控制统一在主页下方，右上角不放调音按钮。** 区分音效音量和语音开关，均在主页统一设置；战斗仍保留“听读音”主操作，不用浮动开关遮挡 HUD。确认现有右上角是语音开关还是音量控件，避免删错。
17. **连续拼对词时的带感语音/音效。** 完整词连胜触发 First Blood、Double Kill、Triple Kill、Quadra Kill、Penta Kill、Rampage、Unstoppable、Godlike 等分层反馈（规范拼写，不改变用户想要的效果）。计数按完整词不是字母，失误/新轮/暂停规则明确；高优先级单词朗读不被播报覆盖，不叠加爆音。先验证系统 TTS 能力，若使用录音素材需合法可分发，不能擅自下载游戏版权声音。
18. **微信浏览器音效兼容或提示系统浏览器。** **已实施静态降级与提示**（`docs/feature-audio-compatibility.md`）：在真实手势内尝试解锁音效，拒绝、挂起超时、无API或朗读真实错误才提示，微信UA只决定说明文案，不直接判故障。提示在主页声音设置下方，可按会话关闭；静音、关闭朗读、正常取消不报故障，不自动改玩家偏好。两路探测定时器与迟到回调独立；后台返回不自动恢复播放。真实游戏页面API失败、取消、关闭提示、320px布局已Chrome验收。**仍未验证**：iOS/Android微信真机实际发声、菜单及后台行为，不能承诺所有微信可听；自动化模拟不等于实际试听。
19. **战斗界面展示所有装备。** 当前遗物、道具、角色被动、剩余次数、护盾等分组紧凑展示；点击看作用，避免把未拥有装备混进来。展示只读状态，与地图/背包/存档唯一来源一致，不挤压320px手机输入区域。

## 建议执行顺序

A阶段 1→2→3→4；然后5→6→7→8→9建立存档和学习主线。C阶段先13建立攻击状态机，再10难度和12多词门槛，最后11角色平衡。D阶段15、16、19可在规则稳定后依次做，再14、17、18。

每项一个实现Agent，之后独立审查与整合回归。需要共享状态/存档协议的5、7、13只允许整合者确认接口后执行。允许针对同一阶段并行只读分析，但用户要求实现依次进行，不同时启动多个玩法写入者。

## 每项交付门禁

- 有可复现失败案例/明确验收条件，测试先失败后通过。
- 单元、集成、真实浏览器与移动尺寸检查；音频注明设备验证范围。
- 旧存档兼容与数据不丢，恢复不重计次数/不重领奖。
- 子智能体自报结果由整合者独立复跑，远端 CI 通过再发布。
- 独立提交/PR，发布后公共地址验证；保留回滚点。
