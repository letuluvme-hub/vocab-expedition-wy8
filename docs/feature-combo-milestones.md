# 战意 · 连击里程碑

第二条成长线。与「知识成长」**并存**，不是它的替代品。

## 为什么需要它

`domain/mastery-growth.js` 是**跨轮次、持久**的线：每掌握 20 个真实教材词 +1 生命上限，
封顶 +12（240 词）。玩家掌握全部 259 词之后，这条线的终点就是终点 —— 新开一轮不再比
上一轮更强。

缺的不是数值，是**维度**。整个游戏此前只有一条成长线，且它的触发条件是「背了多少词」，
和「打得准不准」完全无关。战斗手感上，连击只影响伤害倍率（每 5 连击 +5% 增伤），
没有任何阶段性正反馈 —— 玩家连到第 4 个和第 8 个字母，感觉上没有任何区别。

本功能加的是**技巧线**：触发条件是本词内连击，奖励是当轮的战斗资源。
于是两条线各答一个问题：

| | 知识成长 | 战意（本功能） |
|---|---|---|
| 触发 | 掌握真实教材词 | 连续答对字母 |
| 周期 | 跨轮次、持久 | 本轮内，不落盘 |
| 奖励 | 下轮生命上限 +1（封顶 +12） | 当轮护盾 / 生命 / 提示 |
| 回答的问题 | 「你学了多少」 | 「你打得多准」 |

## 阶梯

| id | 连击 | 名称 | 效果 | 数量 |
|---|---|---|---|---|
| `steady` | 6 | 稳住 | 护盾 +8 | `data/combo-milestones.js` |
| `flow` | 10 | 回气 | 回复生命 | 8 |
| `insight` | 12 | 开悟 | 提示次数 | +1 |

### 门槛为什么是 6 / 10 / 12

连击 `B.combo` 是「**本词内**连续答对的字母数」—— `app/combat.js` 在整词拼完时把它清零，
答错也清零。所以连击的上限是**单词的字母数**，不是累计值。

按 259 个教材词的字母数统计：≥6 字母 175 词、≥8 字母 90 词、≥10 字母 37 词、
≥12 字母 12 词、≥13 字母只有 2 词。所以：

- 6 = 多数词够得着，早期战斗就能碰到；
- 10 = 需要长词，或配合道具「闪电」（下一个正确字母 +3 连击）用 7 字母的词去够；
- 12 = 稀有但真的存在（12 个词达到），只可能在深层/首领战出现。

再往上（例如 14）全库只有 1 个词能达到，等于一个永远不发的奖励 —— 所以阶梯止步于 12。

### 为什么三种效果互不重叠

连击每 5 已经加一次增伤（`B.dmgBonus`）。再来一条伤害线只会让玩家分不清奖励从哪来，
也会挤进难度曲线的伤害公式。所以三阶给的是三种**不同用途**的既有资源：

- 护盾（挨打**前**）→ 与道具「石之护盾」同一口径，夹在生命上限内；
- 生命（挨打**后**）→ 夹在生命上限内，满血时到账 0；
- 提示（答错**后**）→ 直接 +1 次，不受生命上限约束。

**本功能不碰 `WORD_DMG_CAP`、`hpMax` 公式，也不碰难度曲线的任何缩放。**
所有效果都是往既有字段上加，且是**增量**（接线层 `+=` 即可，不会写出越界值）。

## 一轮一次

护盾会跨战斗结转（`domain/run.js` 的 `finishBattleNode` 把 `B.shield` 写回 `run.shield`）。
如果每个里程碑每场战斗都发一次，「打得越多盾越厚」就成了自我强化循环。
所以记在 **run 级**的 `run.milestones`（`id → true` 的普通对象，不是 Set）上，一轮只发一次。
一轮合计：+8 护盾 / +8 生命 / +1 提示。

## 跟着快照走

`run.milestones` 记在 `run-snapshot.js` 的**可选**字段 `milestones` 上，形状与
`growth` 同款：**合法且非空时才写这个键**（空表与缺失都不出现），解码时**缺失回落成空表 `{}`**，
脏值（不是普通对象 / 值不是 `true` / 未登记的 id）**整份 fail closed** —— 内存态脏时
`encodeSnapshot` 直接返回 `null`，绝不存一份缺了里程碑的快照。

**为什么必须落盘**：早先 `encodeRun` 白名单里没有这个键，于是「暂停 → 刷新 → 继续」
把整张表清空，接线层按「本轮一阶都没发过」重新发一遍。护盾与生命都夹在生命上限内，
反复领的上限只是顶满（无害）；**提示次数没有上限**，那是可以无限重刷的实质性漏洞。
把「认不出来」伪装成「还没发过」正是这个漏洞本身，所以两个方向都 fail closed。

解码后的形状与内存态**逐字段相同**（普通对象，不是 Set），所以 `app/combat.js`
与战意条一行都不用改。

## 分层

| 文件 | 职责 |
|---|---|
| `src/data/combo-milestones.js` | 阶梯表（数值唯一来源，无 DOM / 状态 / 存档） |
| `src/domain/combo-milestones.js` | 纯规则：跨没跨过、到账多少、进度视图 |
| `src/app/combat.js` | 接线：按返回值加到既有字段 + toast + 音效 |
| `src/ui/components/combo-milestones.js` | 纯只读展示（容器缺席时安静返回） |
| `src/ui/screens/fight.js` | 每帧把 `G.milestones` / `B.combo` 交给组件 |
| `src/styles/combo-milestones.css` | 只作用于 `.comboMs` 及其自有类名 |

## 契约要点

1. **向上跨越**：判据是 `combo >= 门槛`（配合一轮一次的 fired 表），
   不是 `combo === 门槛`。闪电道具一次 +3 会让连击从 8 跳到 11，里程碑 10 仍要发。
2. **纯函数**：规则层不改入参、不改 fired、不改 battle / run。发放是接线层的责任。
3. **脏入参 fail closed**：combo 是字符串 / 布尔 / NaN / 负数时按 0 处理（**不做
   `Number(x)` 归一** —— `'6'` 是脏的而不是 6）；fired 缺失或形状不对时按「本轮没发过」
   处理；到账量永远是夹好的非负整数。
4. **文案诚实**：到账 0 时写「护盾已满，未额外获得」，绝不报一个玩家没拿到的 `+8`。
5. **展示层纯只读**：渲染前后 G / B 逐字段不变。容器缺席时不抛错、不弄崩整屏。
6. **textContent 落屏**：门槛数字来自存档 / 词库，拼进 innerHTML 就是注入面。
