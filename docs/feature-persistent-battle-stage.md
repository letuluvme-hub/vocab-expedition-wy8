# 保留对峙画面与持续眨眼

双方血条、玩家、怪物、敌人蓄力留在独立 fBattleStage 中；释义、选词、道具与装备进入 fmid 内部滚动。键盘、共用提示次数和四个操作按钮留在可视区。怪种机制标签移到词卡里，减少对峙区高度；横屏左右排列详情与输入，低高度压缩字体、字母键和工具条。

原 renderFight 每次输入都重建怪物 SVG，眼睑动画不断从头开始。现按头像宿主与怪物图形缓存；形象真的改变时才替换。持续 4.8 秒的短促连眨，负延迟错开，不改既有像素身体。普通命中、完整词大招依然走外壳动画；新增舞台不形成层叠上下文，大招文字/冲击波在头像之上，HUD 仍在特效之上。真实 elementFromPoint 叠层探针先失败再通过，防止舞台背景挡住命中特效；减少动态效果偏好关闭眼睑和呼吸。

修改：index.html 对峙容器；ui/screens/fight.js 缓存；pixel-art.css 眨眼；新增 scoped battle-stage.css；样式注册及 extraction 归档骨架精确归一化；battle-stage 浏览器回归。七张冻结样式表字节不变，原有角色部件、控件 id 与规则保留。

失败测试先于实现：390×844、375×667、320×568、844×390 查看全部装备后，头像、双方血条和暂停仍在屏内；真实点击无需 force。横屏额外逐键检查与元素间距，防止控制条、共用次数或底部按钮盖住键盘。真实输入 fa 后 SVG/眼睑节点仍是同一个，采样睁闭变换，减少动态效果关闭动画。

变异：强制每次 renderFight 重建 SVG，动画保持断言失败（退出 1），恢复通过。布局开发中逐键检查发现横屏 min-height 从冻结表继承导致键宽变小但键高仍 40；用新 scoped CSS 修复，不放宽断言。完整命令、退出码与实际数量见合并发布报告。

本轮浏览器测试为 Chromium 141 的 headless shell；未使用安卓/iPhone 真机验收浏览器工具栏、安全区及触摸操作。保留对峙会减少极矮屏详情同时可见面积，详情区需滚动。
