# 平板显示方式

平板主页「开始游戏」和新手引导下面有一排「显示方式」按钮，有自动、手机版式、电脑版式三档。手机和电脑上不出现。

## 为什么要有

全站版式靠宽度断点切换：640 以下是手机单列，900 以上是电脑左右分栏。平板正好卡在中间。
竖屏 iPad Pro 宽 1024，会套电脑分栏，题目卡和字母盘挤在上半屏，下半屏空着；
820 宽的平板走单列，但字母键还是手机尺寸，显得小。孩子用平板时，家长可以按手感自己选。

## 怎么实现

不另写一套 CSS，只改 `<meta name="viewport">` 的 width，让浏览器按指定宽度排版、再等比铺满屏幕。

| 方式 | 竖屏 | 横屏 |
|---|---|---|
| 自动 | device-width（原样） | device-width（原样） |
| 手机版式 | 480 宽，手机单列放大 | 640 宽，手机横握的左右分栏 |
| 电脑版式 | 1024 宽，电脑分栏 | 设备宽度不足 1024 才改成 1024 |

横屏的手机版式用 640，正好落在手机横握的左右分栏上。

转屏时监听 `(orientation: landscape)`，手机版式在 480 和 640 之间换。meta 内容没变就不写，避免 resize 循环。

## 谁能看到

有触屏（`navigator.maxTouchPoints > 0`）、没命中电脑判定、屏幕短边 ≥ 600 CSS 像素，三条都满足才算平板。只看电脑判定不够，它看的是当前窗口宽度，非触屏电脑把窗口拉窄也会漏过来。iPadOS Safari 报桌面 UA、接触控板还会命中 `pointer:fine`，所以「Macintosh + maxTouchPoints > 1」也算平板。电脑浏览器忽略 meta viewport，给了选项也不起作用，所以不给。

## 存在哪

本机 `localStorage` 的 `wy8a_display_v1`，值是 `phone` 或 `desktop`；选回自动就删掉这个键。不进 `wy8a_rogue_v1` 学习存档，清档不影响它。读不出来按自动处理；存不进去（存储被禁用）时，点了当次照样生效，下次打开回到自动。非平板设备上即使存了值也不生效。

## 顺带修的中间宽度战斗页

原来宽 641–899 的窗口两头不靠：不吃 `max-width:640px` 的手机紧凑规则，也不到 900 的电脑分栏。双方战况 221px、字母盘 222px 照电脑尺寸算，820×700 时题目区只剩 4px，820×529 直接是 0。

改在 `battle-stage.css` / `battle-details.css` 两张新增表里，冻结的七张没动：

- 高 481 以上：手机紧凑规则的条件扩到 `max-width:899px`，战况区缩到 120px 上下，字母盘 188px（高不过 620 时 140px）
- 高 481–600：借用手机横握的左右分栏（原条件是宽 640 以上且高不过 480），题目卡在左、字母盘在右，字母盘撑满右栏
- 宽 640 以下、900 以上、以及真正的手机横屏（高不过 480）规则不变

回归测试 `tests/e2e/mid-width-battle.spec.js` 在 8 个尺寸下检查题目区不用滚动就完整可见、字母键都在字母盘里、页面不滚动、不横向溢出。改动前的 CSS 在 641×481 就会失败。

## 验证

- `tests/unit/display-mode.test.js`：宽度规则、平板判定、偏好存取、转屏、组件契约
- `tests/e2e/display-mode.spec.js`：820×1180 平板模拟下三档切换后 `innerWidth` 真的变成 480 / 1024 / 820，刷新后保留，手机版式战斗页是单列且题目卡在字母盘上方；手机上不出现
- `tests/e2e/mid-width-battle.spec.js`：见上
- 未验证：iPad Safari 与安卓平板真机上改 meta viewport 后的缩放表现（Chromium 模拟与真机可能有差异）
